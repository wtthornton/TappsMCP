## Loop

- **State:** Read this file’s progress checklist; `git status -sb`; brain recall for current story key; `get_issue` on the next non-Done child in order 5269→5268→5270→5271→5272→5274→5273→5277→5278→5276→5275.
- **Decide:** Pick the first non-Done child in that order. Skip only with a pasted Blocked reason verified by the verifier.
- **Execute:** Implement that story only (TDD where AC implies tests). Use `tapps_lookup_docs` before external library APIs. Prefer `tapps_call_graph` / impact tools when changing public APIs.
- **Verify (independent):** Spawn a **fresh-context verifier subagent** (frontier) prompted to *refute* the story’s AC. It must re-run the named pytest targets and, where relevant, call the MCP tool under test — not trust the executor’s narration. Default to “not done” on doubt.
- **On fail:** diagnose (error + state + brain) → hypothesis → different fix → retry; ≤3 distinct strategies, then escalate once (stronger model / narrower repro), then stop with a concise diagnosis. Never repeat the same failing command unchanged.
- **Record:** `uv run tapps-mcp memory save --key "metrics-epic/<TAP-ID>" --tier procedural --value "<outcome; failures; PR>"`; comment on Linear with evidence.
- **Context hygiene:** prune stale full-file reads; carry a compact state table (story → status → proof one-liner); targeted grep over re-Read.
- **Repeat or stop:** until Done-when; caps: **40 iterations** AND **≈$40** projected tool/model spend (hard-stop once if next step would exceed remaining budget). Print each iteration: `SCORE story=<id> status=<...> verify=<pass|fail|blocked>`.
